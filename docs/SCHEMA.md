# โครงสร้างฐานข้อมูล E-Borrow

Postgres บน Supabase · สร้างจาก `supabase/migrations/001_schema.sql`
เวลาเก็บเป็น `timestamptz` — หน้าเว็บได้รับเป็น ISO 8601 + เขตเวลาไทย เช่น `2026-09-22T14:30:00+07:00`
ทุกตารางปิดด้วย RLS — หน้าเว็บเข้าถึงได้ผ่านฟังก์ชัน `api()` เท่านั้น

---

## กฎที่ระบบยึดถือ

**สำหรับของที่คืนได้:**
```
available_qty + reserved_qty + out_qty  =  total_qty
```

**สำหรับของสิ้นเปลือง:**
```
available_qty + reserved_qty  =  total_qty        (out_qty เป็น 0 เสมอ)
```

ระบบตรวจทุกคืน ถ้ายอดไม่ตรงจะขึ้นแถบแดงบนแดชบอร์ดครู (ตาราง `reconcile_reports`)
ฐานข้อมูลยังมี `CHECK` กันตัวนับติดลบอีกชั้นหนึ่ง

**ความหมายของตัวนับ 3 ตัว**

| ตัวนับ | หมายความว่า | อยู่ที่ไหนจริง |
|---|---|---|
| `available_qty` | ว่าง พร้อมให้ยืม | บนชั้น |
| `reserved_qty` | มีคนขอจองไว้ รอครูจ่าย | **บนชั้น** (ยังไม่ได้ส่งมอบ) |
| `out_qty` | ส่งมอบไปแล้ว รอคืน | อยู่กับนักเรียน |

> ที่ต้องแยก `reserved` กับ `out` เพราะถ้ามีแค่ตัวเดียว ครูจะรับปาก
> มัลติมิเตอร์ตัวสุดท้ายให้นักเรียน 2 คนพร้อมกันได้

## ตาราง `students`

| คอลัมน์ | ความหมาย |
|---|---|
| `student_id` | รหัสนักศึกษา (คีย์หลัก ใช้เข้าระบบ) — เก็บเป็น `text` เลข 0 นำหน้าไม่หาย |
| `full_name` | ชื่อ-สกุล |
| `level` / `department` / `section` | ระดับชั้น / สาขาวิชา / กลุ่ม |
| `phone` | เบอร์โทร (ไว้ตามของ) |
| `pin_hash` | PIN ที่เข้ารหัสแล้ว (bcrypt) — **ไม่ใช่ PIN จริง** |
| `status` | `PENDING` รออนุมัติ · `ACTIVE` ใช้ได้ · `SUSPENDED` ระงับ · `GRADUATED` จบแล้ว |
| `role` | `STUDENT` หรือ `ADMIN` |
| `failed_pin_count` / `locked_until` | นับการใส่ PIN ผิด / ล็อกถึงเมื่อไร |
| `active_loan_count` | จำนวนรายการที่ยืมค้างอยู่ (ใช้เช็กโควต้า) |
| `overdue_count` | จำนวนรายการเกินกำหนด (ใช้บล็อกการยืมใหม่) |

| `available_qty` | ว่างให้ยืมกี่ชิ้น |

| `status` | `ACTIVE` · `HIDDEN` ซ่อน · `RETIRED` เลิกใช้ |

## ตาราง `transactions` — 1 แถว = 1 คำขอ (1 ตะกร้า)

| คอลัมน์ | ความหมาย |
|---|---|
| `txn_id` | เลขที่รายการ เช่น `TXN-20260922-0001` |
| `student_id` | ใครยืม |
| `student_name_snapshot` | ชื่อ ณ ตอนยืม (ถ้าแก้ชื่อทีหลัง ประวัติเดิมไม่เปลี่ยน) |
| `status` | ดูตารางสถานะด้านล่าง |
| `requested_at` | ขอเมื่อไร |
| `issued_at` | **ได้รับของจริงเมื่อไร** — กำหนดคืนนับจากตรงนี้ |
| `due_at` | ครบกำหนดคืน |
| `returned_at` | คืนครบเมื่อไร |
| `outstanding_qty` | ยังค้างกี่ชิ้น — **เหลือ 0 = ปิดรายการ** |
| `return_photo_path` / `return_photo_url` | รูปตอนคืนใน bucket `return-photos` |
| `return_photo_deleted_at` | ลบรูปไปแล้วเมื่อไร (เก็บครบ `return_photo_retention_days`) |

## ตาราง `transaction_lines` — 1 แถว = 1 อุปกรณ์ในตะกร้า

| คอลัมน์ | ความหมาย |
|---|---|
| `line_id` | เช่น `TXN-20260922-0001-L1` |
| `item_name_snapshot` | ชื่ออุปกรณ์ ณ ตอนยืม |
| **`is_consumable_snapshot`** | เป็นของสิ้นเปลืองไหม **ณ ตอนยืม** — ถ้าครูเปลี่ยน flag ทีหลัง ประวัติเก่าต้องไม่เปลี่ยนตาม |
| `qty_requested` | นักเรียนขอ |
| `qty_approved` | ครูอนุมัติ (ลดได้) |
| `qty_issued` | จ่ายจริง |
| `qty_returned` / `qty_lost` | คืนแล้ว / แจ้งหาย |
| `line_status` | `PENDING` `APPROVED` `ISSUED` `RETURNED` `PARTIALLY_RETURNED` **`CONSUMED`** `LOST` `CANCELLED` |

> `CONSUMED` แยกจาก `RETURNED` เพราะของสิ้นเปลืองจบตั้งแต่ตอนจ่าย
> ถ้าใช้สถานะเดียวกันจะตอบไม่ได้ว่า "ของที่ได้คืนมาจริงๆ มีอะไรบ้าง"

## ตาราง `stock_ledger` — ประวัติทุกการเปลี่ยนแปลง (เพิ่มอย่างเดียว ไม่แก้)

บันทึกทุกครั้งที่จำนวนเปลี่ยน พร้อมค่าก่อน-หลัง
**นี่คือสิ่งเดียวที่ตอบได้ว่า "ตัวต้านทานหายไป 20 ตัวตอนไหน ใครเอาไป"**

`event_type` ที่เป็นไปได้:

| ค่า | เกิดเมื่อ |
|---|---|
| `RESERVE` | นักเรียนกดยืม (จองไว้) |
| `UNRESERVE` | ยกเลิก / ปฏิเสธ / หมดอายุ |
| `ISSUE` | ครูจ่ายของคืนได้ |
| `CONSUME` | ครูจ่ายของสิ้นเปลือง (หักถาวร) |
| `RETURN` | รับคืน |
| `LOST` | แจ้งหาย/ชำรุด |
| `ADJUST_IN` / `ADJUST_OUT` | ครูเพิ่ม/ลดสต็อกเอง |
| `STOCKTAKE` | ตรวจนับแล้วตั้งค่าใหม่ |

## สถานะรายการยืม

```
REQUESTED ──อนุมัติ──> APPROVED ──จ่ายของ──> IN_USE ──คืน──> RETURNED
    │                     │                    │
    ├─ปฏิเสธ─> REJECTED   │                    ├─คืนบางส่วน─> PARTIALLY_RETURNED
    ├─ยกเลิก─> CANCELLED  │                    └─เลยกำหนด──> OVERDUE ──คืน──> RETURNED
    └─ไม่มารับ─> EXPIRED   └─ถ้าเป็นของสิ้นเปลืองล้วน──> CLOSED_CONSUMED
```

| สถานะ | ความหมาย |
|---|---|
| `REQUESTED` | นักเรียนส่งคำขอ รอครูอนุมัติ (ของถูกจองไว้แล้ว) |
| `APPROVED` | ครูอนุมัติแล้ว **รอนักเรียนมารับของ** |
| `IN_USE` | ของอยู่กับนักเรียน |
| `PARTIALLY_RETURNED` | คืนมาบางส่วน ยังค้างอยู่ |
| `OVERDUE` | เลยกำหนดคืน (ระบบตั้งให้ทุกคืน) |
| `RETURNED` | คืนครบแล้ว ปิดรายการ |
| `CLOSED_CONSUMED` | เป็นของสิ้นเปลืองล้วน จบตั้งแต่จ่าย |
| `EXPIRED` | ขอแล้วไม่มารับภายใน 48 ชม. ระบบคืนของเข้าคลัง |
| `LOST` | แจ้งสูญหาย |

> **`EXPIRED` มีไว้ทำไม:** ถ้าไม่มี นักเรียนที่กดยืมแล้วไม่มารับจะจองของค้างไว้ตลอดไป
> จนแคตตาล็อกแสดงว่าของหมดทั้งที่ยังอยู่บนชั้นครบ

## ตารางอื่นๆ

| ตาราง | หน้าที่ |
|---|---|
| `categories` | หมวดหมู่อุปกรณ์ |
| `sessions` | การเข้าสู่ระบบที่ยังใช้งานได้ (token เก็บแบบ hash · ล้างอัตโนมัติทุกคืน) |
| `config` | ค่าตั้งค่าที่ครูแก้เองได้ |
| `audit_log` | บันทึกทุกการกระทำ + **ทุกครั้งที่ถูกปฏิเสธ** (ใช้ดูว่ามีคนพยายามเดา PIN ไหม) · เก็บ 1 ปี |
| `idempotency` | คำตอบของคำขอที่เพิ่งทำ — กดซ้ำ/ส่งซ้ำได้คำตอบเดิม ไม่ยืมซ้ำ (ล้างทุกคืน) |
| `daily_counters` | ตัวนับเลขรายการยืมรายวัน |
| `pending_returns` | การคืนที่เริ่มแล้วแต่ยังไม่กดยืนยัน |
| `upload_tickets` | ตั๋วอัปรูปใช้ครั้งเดียว หมดอายุใน 1 ชั่วโมง |
| `storage_delete_queue` | ไฟล์รูปที่รอ Edge Function `storage-cleanup` ลบ |
| `reconcile_reports` | ผลกระทบยอดรายคืนที่ไม่ตรง (แสดงบนแดชบอร์ด) |
| `app_secrets` | `PIN_PEPPER` — ห้ามแก้ (PIN ทุกคนจะใช้ไม่ได้) |
| `error_messages` | ข้อความ error ภาษาไทยของแต่ละรหัส |

## ⚠️ ข้อควรระวังเมื่อแก้ข้อมูลเองใน Table Editor

| ทำได้ | ห้ามทำ |
|---|---|
| ✅ แก้ค่าในตาราง `config` | ❌ ลบแถวใน `transactions` / `transaction_lines` |
| ✅ แก้ชื่อ/ตำแหน่งเก็บใน `items` | ❌ แก้ตัวเลข `available_qty` ตรงๆ (ใช้ปุ่ม "ปรับสต็อก" แทน) |
| ✅ ดู `audit_log` / `stock_ledger` | ❌ แก้ `app_secrets` |
