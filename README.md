# E-Borrow — ระบบยืม-คืนอุปกรณ์ห้องเรียน

ระบบยืม-คืนอุปกรณ์สำหรับห้องเรียนอิเล็กทรอนิกส์ หน้าตาแบบร้านค้าออนไลน์ แต่ยืมแล้วต้องคืน
**ฟรี 100% ไม่ต้องเช่าเซิร์ฟเวอร์**

```
[มือถือนักเรียน] → [GitHub Pages]  →  [Apps Script]  →  [Google Sheets]
                    หน้าเว็บ (ฟรี)      หลังบ้าน (ฟรี)     ฐานข้อมูล (ฟรี)
                                             ↓
                                      [Google Drive] รูปตอนคืน (ฟรี)
```

---

## ⚠️ กฎข้อเดียวที่ห้ามลืม

เวลาแก้โค้ดฝั่ง Apps Script แล้วต้องการให้เว็บใช้โค้ดใหม่:

> **Deploy → Manage deployments → กดดินสอ ✏️ แก้อันเดิม → Version: New version → Deploy**

**ห้ามกด "New deployment"** เพราะจะได้ URL ใหม่ และเว็บจะพังทันที

## ติดตั้งครั้งแรก (ทำครั้งเดียว ~30 นาที)

### ขั้นที่ 1 — สร้าง Google Sheets

1. เปิด [sheets.google.com](https://sheets.google.com) สร้างสเปรดชีตใหม่
2. ตั้งชื่อว่า `E-Borrow Database`
3. **อย่าแชร์ให้ใคร** — ไฟล์นี้มีข้อมูลนักเรียนทั้งหมด ระบบเข้าถึงแทนครูเอง

### ขั้นที่ 2 — สร้าง Apps Script

1. ในสเปรดชีต เมนู **ส่วนขยาย (Extensions) → Apps Script**
2. ลบไฟล์ `Code.gs` ที่มีอยู่ทิ้ง
3. สร้างไฟล์ใหม่ทีละไฟล์ (กด **+ → Script**) แล้ววางโค้ดจากโฟลเดอร์ `apps-script/`

   ต้องมีครบ 11 ไฟล์ **ชื่อต้องตรงกัน** (ไม่ต้องใส่ `.gs` ตอนตั้งชื่อ):

   | ไฟล์ | หน้าที่ |
   |---|---|
   | `Util` | ฟังก์ชันพื้นฐาน วันที่ การเข้ารหัส |
   | `Sheets` | อ่าน/เขียนชีต + สร้างชีตครั้งแรก |
   | `Config` | ค่าตั้งค่าระบบ |
   | `Auth` | สมัคร เข้าสู่ระบบ ตรวจสิทธิ์ |
   | `Stock` | คำนวณสต็อก (แกนความถูกต้อง) |
   | `Catalog` | รายการอุปกรณ์ |
   | `Borrow` | การยืม |
   | `Return` | การคืน + รูปถ่าย |
   | `Admin` | งานของครู |
   | `Triggers` | งานอัตโนมัติรายคืน |
   | `Main` | ตัวรับคำสั่งทั้งหมด |

4. แก้ไฟล์ `appsscript.json` ให้ตรงกับในโฟลเดอร์นี้
   (ถ้าไม่เห็นไฟล์: ⚙️ **Project Settings** → ติ๊ก *Show "appsscript.json"*)

### ขั้นที่ 3 — สร้างชีตและบัญชีครู

ในหน้า Apps Script เลือกฟังก์ชันแล้วกด **Run** ตามลำดับ:

1. **`setupSpreadsheet`** — สร้างทุกแท็บ ค่าตั้งต้น และรหัสลับ
   - ครั้งแรกจะขออนุญาต → **Review permissions → เลือกบัญชี → Advanced → Go to (unsafe) → Allow**
   - คำว่า "unsafe" เป็นเรื่องปกติ เพราะเป็นสคริปต์ที่เราเขียนเอง ยังไม่ผ่านการรับรองจาก Google

2. เปิดไฟล์ `Auth.gs` หาฟังก์ชัน `createAdminAccount()` ใกล้ท้ายไฟล์
   แก้ 3 บรรทัดนี้:
   ```js
   var ADMIN_ID   = '000000';          // รหัสที่ครูใช้เข้าระบบ
   var ADMIN_NAME = 'ครูผู้ดูแลระบบ';   // ชื่อครู
   var ADMIN_PIN  = '123456';          // ต้อง 6-8 หลัก
   ```

3. **Run `createAdminAccount`** → ได้บัญชีครูแล้ว
   > 🔒 หลังจากนี้ **ลบ PIN ออกจากโค้ด** (เปลี่ยนเป็น `''`) และเข้าระบบไปเปลี่ยน PIN ทันที

4. **Run `installTriggers`** — ตั้งงานอัตโนมัติรายคืน
   (เช็กของเกินกำหนด ปล่อยการจองที่ค้าง กระทบยอดสต็อก)

### ขั้นที่ 4 — Deploy

1. กด **Deploy → New deployment**
2. ⚙️ ข้าง "Select type" → เลือก **Web app**
3. ตั้งค่า **สำคัญมาก**:
   - Execute as: **Me (อีเมลของครู)**
   - Who has access: **Anyone** ← ต้องเป็น "Anyone" ไม่ใช่ "Anyone with Google account"
4. กด **Deploy** → **คัดลอก Web app URL** (ลงท้ายด้วย `/exec`)

> ถ้าเลือก "Anyone with Google account" นักเรียนจะต้องล็อกอิน Google ก่อน
> และจะเจอหน้าขออนุญาตที่น่ากลัว

### ขั้นที่ 5 — ตั้งค่าและอัปหน้าเว็บขึ้น GitHub Pages

1. แก้ไฟล์ `web/js/config.js` บรรทัด `API_URL` ให้เป็น URL ที่คัดลอกมา:
   ```js
   API_URL: 'https://script.google.com/macros/s/AKfycb..../exec',
   ```

2. สร้าง repo ใหม่บน GitHub (เช่นชื่อ `e-borrow`) แล้วอัปโหลด**ทุกไฟล์ในโฟลเดอร์ `web/`**
   ขึ้นไปไว้ที่ราก repo

3. แก้ `BASE_PATH` ใน `config.js` ให้ตรงกับที่อยู่จริง:
   ```js
   BASE_PATH: '/e-borrow/',   // ถ้า repo ชื่อ e-borrow
   BASE_PATH: '/',            // ถ้า repo ชื่อ username.github.io
   ```

4. ใน repo: **Settings → Pages → Source: Deploy from a branch → main → / (root) → Save**

5. รอ 1-2 นาที แล้วเปิด `https://<username>.github.io/e-borrow/`

### ขั้นที่ 6 — ทดสอบว่าเชื่อมต่อได้จริง ⭐

**ข้อนี้สำคัญที่สุด อย่าข้าม**

1. เปิดหน้าเว็บ กด **F12 → Console**
2. พิมพ์:
   ```js
   API.read('ping').then(console.log)
   ```
3. ต้องได้ `{pong: true, version: "1.0.0", timeZone: "Asia/Bangkok"}`

**ถ้าขึ้น CORS error** แปลว่าตั้งค่า deploy ผิด กลับไปเช็กขั้นที่ 4
(Execute as = Me, Who has access = Anyone)

## เริ่มใช้งาน

1. เข้าระบบด้วยบัญชีครู → **เปลี่ยน PIN ทันที**
2. ไปหน้า **อุปกรณ์** → กด "หมวดหมู่" เพิ่มหมวดก่อน เช่น
   เครื่องมือวัด · เครื่องมือช่าง · อุปกรณ์อิเล็กทรอนิกส์ · เครื่องเขียน
3. กด **+ เพิ่มอุปกรณ์** ใส่ข้อมูล

   > **ติ๊ก "ของสิ้นเปลือง" ให้ถูก** — ตัวต้านทาน ตะกั่วบัดกรี สายไฟ = สิ้นเปลือง
   > (จ่ายแล้วตัดสต็อกถาวร ไม่รอคืน)
   > หัวแร้ง มัลติมิเตอร์ ไม้บรรทัด = คืนได้

   > **ใส่ "ตำแหน่งเก็บ" ด้วย** เช่น `ตู้ A ชั้น 2`
   > ระบบจะทำใบรายการหยิบของเรียงตามตู้ให้ ทำให้หยิบของรอบเดียวจบ

4. ให้นักเรียนเข้าเว็บ กด **สมัครใช้งาน**
5. ครูไปหน้า **นักเรียน** กดอนุมัติ

## ขั้นตอนการใช้งานประจำวัน

| ใคร | ทำอะไร |
|---|---|
| นักเรียน | เลือกอุปกรณ์ใส่ตะกร้า → กดส่งคำขอ |
| **ครู** | หน้า **คำขอยืม** → ดูใบรายการหยิบของ → หยิบของ → กด **"อนุมัติ + จ่ายของเลย"** |
| นักเรียน | ใช้งาน |
| นักเรียน | จบคาบ → **คืนอุปกรณ์** → **ถ่ายรูป** → กดยืนยัน |
| ครู | เก็บของเข้าตู้ · ดูแดชบอร์ดว่าใครยังไม่คืน |

> ถ้านักเรียนถ่ายรูปไม่ได้ ครูกด **"รับคืน"** จากหน้าแดชบอร์ดแทนได้

## ปรับแต่งระบบ

แก้ที่แท็บ **Config** ในสเปรดชีตได้เลย (แก้แล้วมีผลใน 5 นาที)

| key | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `default_due_days` | 7 | ให้ยืมกี่วัน (**ใส่ 0 = คืนภายในวันนี้/จบคาบ**) |
| `max_active_loans_per_student` | 5 | ยืมค้างได้กี่รายการพร้อมกัน |
| `block_borrow_if_overdue` | TRUE | มีของเกินกำหนดแล้วห้ามยืมเพิ่ม |
| `require_photo_on_return` | TRUE | บังคับถ่ายรูปตอนคืน |
| `auto_approve_requests` | FALSE | อนุมัติอัตโนมัติ (ยังต้องกดจ่ายของอยู่) |
| `request_expiry_hours` | 48 | ไม่มารับของกี่ชั่วโมงแล้วยกเลิก |
| `pin_iterations` | 10000 | ความแรงการเข้ารหัส (ลดเป็น 5000 ถ้าเข้าระบบช้า) |
| `levels_json` | ปวช.1-ปวส.2 | ตัวเลือกระดับชั้นตอนสมัคร |
| `departments_json` | — | ตัวเลือกสาขาวิชาตอนสมัคร |

**อุปกรณ์แต่ละชิ้นตั้งวันคืนเองได้** ที่ช่อง "กำหนดคืน (วัน)" เช่น
มัลติมิเตอร์ = 0 (คืนจบคาบ) แต่ไม้บรรทัด = 7 วัน

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| **CORS error / เชื่อมต่อไม่ได้** | Deploy ผิด — ต้อง Execute as **Me** + Access **Anyone** |
| **เว็บพังหลังแก้โค้ด** | กด "New deployment" ไปแล้ว → ใช้ **Manage deployments → ✏️ → New version** |
| **"เซิร์ฟเวอร์ตอบกลับผิดรูปแบบ"** | URL ใน `config.js` ผิด หรือยังไม่ได้ deploy |
| **นักเรียนเจอหน้าขออนุญาต Google** | Access ตั้งเป็น "Anyone with Google account" → เปลี่ยนเป็น **Anyone** |
| **รหัสนักศึกษาเลข 0 นำหน้าหาย** | คอลัมน์ `student_id` ต้องเป็นรูปแบบ "ข้อความ" (`setupSpreadsheet` ตั้งให้แล้ว) |
| **รูปไม่ขึ้น** | Google อาจเปลี่ยนวิธีลิงก์รูป — แก้ที่ฟังก์ชัน `driveThumbnailUrl_()` ใน `Return.gs` จุดเดียว |
| **"ระบบกำลังยุ่ง"** | คนกดพร้อมกันเยอะ ระบบจะลองใหม่ให้เอง 3 ครั้ง |
| **ลืม PIN** | ครูไปหน้า **นักเรียน → รีเซ็ต PIN** |
| **สต็อกเพี้ยน** | ระบบส่งอีเมลแจ้งครูอัตโนมัติทุกคืน · แก้มือได้ที่ "ปรับสต็อก" |

## ความปลอดภัย

- **PIN ไม่ได้เก็บตรงๆ** — เข้ารหัสด้วย SHA-256 วนซ้ำ 10,000 รอบ + salt รายคน + **pepper**
- **pepper เก็บใน Script Properties ไม่ใช่ในชีต** — ถ้าสเปรดชีตหลุดออกไป รหัสก็ยังถอดไม่ได้
- ใส่ PIN ผิด 5 ครั้ง → ล็อก 15 นาที
- ห้ามใช้ PIN ที่เดาง่าย (1234, 1111, 0000 ฯลฯ)
- ระบบไม่บอกว่ารหัสนักศึกษามีจริงหรือไม่ (กันการไล่เดารายชื่อ)
- ทุกการกระทำถูกบันทึกในแท็บ `AuditLog`

> **รูปตอนคืนถูกตั้งเป็น "ใครมีลิงก์ก็เปิดดูได้"** เพื่อให้แสดงบนเว็บได้โดยไม่กินโควต้า
> เป็นรูปอุปกรณ์แล็บจึงรับได้ — แต่อย่าใช้ระบบนี้เก็บอะไรที่เป็นความลับ

## ข้อควรรู้เกี่ยวกับสเปรดชีต

เปิดดูและแก้ข้อมูลเองได้ แต่:

- ❌ **อย่าแก้แถวแรก (header)** — ระบบอ้างอิงชื่อคอลัมน์
- ❌ **อย่าลบแถวใน `Transactions` / `TransactionLines`** — จะทำให้ยอดสต็อกเพี้ยน
- ✅ เรียงลำดับแถว เพิ่มคอลัมน์ใหม่ท้ายตาราง หรือแก้ใน `Config` ได้ปลอดภัย
- ✅ `StockLedger` คือประวัติทุกการเปลี่ยนแปลง ใช้ตรวจสอบว่าของหายตอนไหน
