# E-Borrow — ระบบยืม-คืนอุปกรณ์ห้องเรียน

ระบบยืม-คืนอุปกรณ์สำหรับห้องเรียนอิเล็กทรอนิกส์ หน้าตาแบบร้านค้าออนไลน์ แต่ยืมแล้วต้องคืน
**ฟรี 100% ไม่ต้องเช่าเซิร์ฟเวอร์**

```
[มือถือนักเรียน] → [GitHub Pages]  →  [Supabase: Postgres]   ข้อมูลทั้งหมด + กฎสต็อก
                    หน้าเว็บ (ฟรี)  ↘  [Supabase: Storage]    รูปตอนคืน / รูปอุปกรณ์
```

ตอบสนองราว 0.1–0.3 วินาทีต่อคำสั่ง

---

## ติดตั้งครั้งแรก (~30 นาที)

### ขั้นที่ 1 — สร้างโปรเจกต์ Supabase

1. สมัครที่ [supabase.com](https://supabase.com) (ใช้บัญชี GitHub ได้)
2. **New project** → ตั้งชื่อ `e-borrow` → ตั้งรหัสผ่านฐานข้อมูล (จดเก็บไว้)
   → Region: **Southeast Asia (Singapore)** → Create

### ขั้นที่ 2 — สร้างฐานข้อมูล

ในโปรเจกต์ เมนู **SQL Editor** → **New query** → วางเนื้อหาไฟล์ทีละไฟล์แล้วกด **Run** ตามลำดับ:

```
supabase/migrations/001_schema.sql
supabase/migrations/002_helpers.sql
...
supabase/migrations/011_permissions.sql
supabase/seed.sql
```

จากนั้นรันคำสั่งนี้ (แก้เป็น URL โปรเจกต์ของครู ดูได้ที่ **Project Settings → API**):

```sql
update config set value = 'https://xxxx.supabase.co' where key = 'project_url';
```

### ขั้นที่ 3 — สร้างบัญชีครู

SQL Editor:
```sql
select create_admin('000000', 'ครูผู้ดูแลระบบ', '123456');
```
(รหัสเข้าระบบ / ชื่อ / PIN 6-8 หลัก) → เข้าระบบแล้ว **เปลี่ยน PIN ทันที**

### ขั้นที่ 4 — ตัวลบรูปเก่าอัตโนมัติ

ระบบลบรูปตอนคืนที่เก่ากว่า 4 เดือนทุกคืน เพื่อไม่ให้พื้นที่ฟรี 1 GB เต็ม

1. เมนู **Edge Functions** → **Deploy a new function** → **Via Editor**
2. ตั้งชื่อ `storage-cleanup` → วางโค้ดจาก `supabase/functions/storage-cleanup/index.ts` → Deploy
3. ในหน้าฟังก์ชัน → **Details** → ปิด **Enforce JWT verification** → Save
   (ปลอดภัย — ฟังก์ชันนี้ทำได้แค่ลบไฟล์ที่ระบบสั่งไว้ในคิว)

### ขั้นที่ 5 — ตั้งค่าและอัปหน้าเว็บขึ้น GitHub Pages

1. แก้ไฟล์ `js/config.js` ใส่ค่าจาก **Project Settings → API**:
   ```js
   SUPABASE_URL: 'https://xxxx.supabase.co',
   SUPABASE_ANON_KEY: 'eyJ...',   // anon / publishable key — ห้ามใช้ service_role
   ```
2. แก้ `BASE_PATH` ให้ตรงกับชื่อ repo:
   ```js
   BASE_PATH: '/e-borrow/',   // ถ้า repo ชื่อ e-borrow
   BASE_PATH: '/',            // ถ้า repo ชื่อ username.github.io
   ```
3. push ขึ้น GitHub → repo **Settings → Pages → Source: Deploy from a branch → main → / (root)**

### ขั้นที่ 6 — ทดสอบว่าเชื่อมต่อได้จริง ⭐

เปิดหน้าเว็บ → **F12 → Console** → พิมพ์:
```js
API.read('ping').then(console.log)
```
ต้องได้ `{pong: true, version: "2.0.0", backend: "supabase", ...}`

## เริ่มใช้งาน

1. เข้าระบบด้วยบัญชีครู → **เปลี่ยน PIN ทันที**
2. ไปหน้า **อุปกรณ์** → กด "หมวดหมู่" เพิ่มหมวดก่อน เช่น
   เครื่องมือวัด · เครื่องมือช่าง · อุปกรณ์อิเล็กทรอนิกส์ · เครื่องเขียน
3. กด **+ เพิ่มอุปกรณ์** ใส่ข้อมูล

   > **ติ๊ก "ของสิ้นเปลือง" ให้ถูก** — ตัวต้านทาน ตะกั่วบัดกรี สายไฟ = สิ้นเปลือง
   > (จ่ายแล้วตัดสต็อกถาวร ไม่รอคืน)
   > หัวแร้ง มัลติมิเตอร์ ไม้บรรทัด = คืนได้

   > **ใส่ "ตำแหน่งเก็บ" ด้วย** เช่น `ตู้ A ชั้น 2`
   > ระบบจะทำใบรายการหยิบของเรียงตามตู้ให้ ทำให้หยิบของรอบเดียวจบ

4. ให้นักเรียนเข้าเว็บ กด **สมัครใช้งาน**
5. ครูไปหน้า **นักเรียน** กดอนุมัติ

## ขั้นตอนการใช้งานประจำวัน

| ใคร | ทำอะไร |
|---|---|
| นักเรียน | เลือกอุปกรณ์ใส่ตะกร้า → กดส่งคำขอ |
| **ครู** | หน้า **คำขอยืม** → ดูใบรายการหยิบของ → หยิบของ → กด **"อนุมัติ + จ่ายของเลย"** |
| นักเรียน | ใช้งาน |
| นักเรียน | จบคาบ → **คืนอุปกรณ์** → **ถ่ายรูป** → กดยืนยัน |
| ครู | เก็บของเข้าตู้ · ดูแดชบอร์ดว่าใครยังไม่คืน |

> ถ้านักเรียนถ่ายรูปไม่ได้ ครูกด **"รับคืน"** จากหน้าแดชบอร์ดแทนได้

## ปรับแต่งระบบ

Supabase → **Table Editor → config** แก้ช่อง `value` ได้เลย (มีผลทันที)

| key | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `default_due_days` | 7 | ให้ยืมกี่วัน (**ใส่ 0 = คืนภายในวันนี้/จบคาบ**) |
| `max_active_loans_per_student` | 5 | ยืมค้างได้กี่รายการพร้อมกัน |
| `block_borrow_if_overdue` | TRUE | มีของเกินกำหนดแล้วห้ามยืมเพิ่ม |
| `require_photo_on_return` | TRUE | บังคับถ่ายรูปตอนคืน |
| `return_photo_retention_days` | 120 | เก็บรูปตอนคืนกี่วันแล้วลบอัตโนมัติ (≈ 4 เดือน) |
| `auto_approve_requests` | FALSE | อนุมัติอัตโนมัติ (ยังต้องกดจ่ายของอยู่) |
| `request_expiry_hours` | 48 | ไม่มารับของกี่ชั่วโมงแล้วยกเลิก |
| `levels_json` | ปวช.1-ปวส.2 | ตัวเลือกระดับชั้นตอนสมัคร |
| `departments_json` | — | ตัวเลือกสาขาวิชาตอนสมัคร |
| `announcement` | — | ข้อความประกาศบนหน้าแรก |

**อุปกรณ์แต่ละชิ้นตั้งวันคืนเองได้** ที่ช่อง "กำหนดคืน (วัน)" เช่น
มัลติมิเตอร์ = 0 (คืนจบคาบ) แต่ไม้บรรทัด = 7 วัน

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
|---|---|
| **"เชื่อมต่อฐานข้อมูลไม่ได้"** | `SUPABASE_URL` / `SUPABASE_ANON_KEY` ใน `js/config.js` ผิด หรือยังรัน SQL ไม่ครบ — ดู F12 → Console |
| **เว็บไม่ตอบหลังปิดเทอม** | โปรเจกต์ฟรีถูกพักเมื่อไม่มีคนใช้ 7 วัน → Supabase Dashboard กด **Restore project** (ข้อมูลไม่หาย) · ระบบมี GitHub Action ปลุกทุก 3 วันอยู่แล้ว แต่ GitHub จะหยุด Action เองถ้า repo ไม่มีความเคลื่อนไหว 60 วัน |
| **อัปรูปไม่ขึ้น / ลิงก์รูปเสีย** | ยังไม่ได้ตั้ง `project_url` ในตาราง config (ขั้นที่ 2) |
| **"ระบบกำลังยุ่ง"** | คนกดของชิ้นเดียวกันพร้อมกันเยอะ ระบบจะลองใหม่ให้เอง 3 ครั้ง |
| **ลืม PIN (นักเรียน)** | ครูไปหน้า **นักเรียน → รีเซ็ต PIN** |
| **ลืม PIN (ครู)** | SQL Editor: `select reset_pin_for_user('000000', 'PINใหม่');` |
| **สต็อกเพี้ยน** | ระบบตรวจทุกคืน ถ้าไม่ตรงจะขึ้นแถบแดงบนแดชบอร์ดพร้อมปุ่มแก้ · แก้มือได้ที่ "ปรับสต็อก" |
| **พื้นที่รูปใกล้เต็ม** | แดชบอร์ดเตือนเมื่อเกิน 80% → ลด `return_photo_retention_days` |

## ความปลอดภัย

- หน้าเว็บอ่าน/เขียนตารางตรงๆ ไม่ได้เลย (ทุกตารางปิดด้วย RLS) — ทุกคำสั่งต้องผ่านฟังก์ชัน `api()` ที่ตรวจ token และสิทธิ์
- **PIN เข้ารหัสด้วย bcrypt + pepper** — pepper อยู่ในตาราง `app_secrets` ที่ปิดตาย
- token เข้าระบบเก็บแบบ hash — ข้อมูลหลุดก็เอาไปสวมรอยไม่ได้
- ใส่ PIN ผิด 5 ครั้ง → ล็อก 15 นาที · ห้ามใช้ PIN ที่เดาง่าย (1234, 1111 ฯลฯ)
- ระบบไม่บอกว่ารหัสนักศึกษามีจริงหรือไม่ (กันการไล่เดารายชื่อ)
- อัปรูปได้เฉพาะคนที่ระบบออก "ตั๋ว" ให้ (ใช้ครั้งเดียว หมดอายุใน 1 ชั่วโมง ไฟล์ไม่เกิน 300 KB)
- ทุกการกระทำถูกบันทึกในตาราง `audit_log` (เก็บ 1 ปี)

> **รูปเปิดดูได้ทุกคนที่มีลิงก์** เพื่อให้แสดงบนเว็บได้เร็ว
> เป็นรูปอุปกรณ์แล็บจึงรับได้ — แต่อย่าใช้ระบบนี้เก็บอะไรที่เป็นความลับ

```
├── index.html login.html register.html
├── catalog.html cart.html my-loans.html return.html
├── admin/              ← dashboard, requests, items, students
├── css/styles.css
├── js/                 ← config.js ต้องใส่ SUPABASE_URL / KEY ก่อนใช้
├── supabase/
│   ├── migrations/     ← SQL หลังบ้านทั้งหมด (รันตามลำดับเลข)
│   ├── functions/      ← Edge Function ลบรูปตามคิว
│   ├── seed.sql        ← ค่าตั้งต้น
│   └── tests/          ← ทดสอบ SQL ในเครื่อง: cd supabase/tests && npm install && npm test
├── docs/SCHEMA.md      ← คำอธิบายตาราง
└── .github/workflows/keepalive.yml  ← ปลุกโปรเจกต์ทุก 3 วัน
```

### แก้โค้ดหลังบ้าน

แก้ไฟล์ใน `supabase/migrations/` → รัน `npm test` ใน `supabase/tests/` ให้ผ่าน
→ วางไฟล์ที่แก้ใน SQL Editor แล้วกด Run (ทุกฟังก์ชันเป็น `create or replace` รันซ้ำได้)
→ **รัน `011_permissions.sql` ซ้ำทุกครั้ง** ไม่งั้นฟังก์ชันที่เพิ่งสร้างอาจถูกเรียกตรงจากหน้าเว็บได้

## ข้อควรรู้เกี่ยวกับฐานข้อมูล

เปิดดูข้อมูลได้ที่ **Table Editor** แต่:

- ❌ **อย่าลบแถวใน `transactions` / `transaction_lines`** — จะทำให้ยอดสต็อกเพี้ยน
- ❌ **อย่าแก้ตัวเลขใน `items` ตรงๆ** — ใช้ปุ่ม "ปรับสต็อก" ในหน้าเว็บ จะได้มีประวัติ
- ✅ แก้ตาราง `config` ได้ปลอดภัย
- ✅ `stock_ledger` คือประวัติทุกการเปลี่ยนแปลง ใช้ตรวจสอบว่าของหายตอนไหน
